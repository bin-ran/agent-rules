# 分区规范（Section Spec）

设计稿画布的唯一排版标准。数值来自 binran 项目 V1/V2 双版本、16+ 屏、多品牌板的实战整理。

## 1. Section 几何

| 项 | 值 | 说明 |
|---|---|---|
| 左/右内边距 | `32` | 内容不贴边，视觉呼吸 |
| 上内边距（标题带） | `56` | Figma Section 标题占 ~40px，留 16 余量 |
| 下内边距 | `32` | |
| Section 之间间距 | `200` | 足够区分「区块」，又不至于离得找不到 |
| 起点 | `x = 0`，`y = 前一个 y + height + 200` | 单列垂直流，永不横向漂移 |

Section 上的元素坐标是**相对 Section** 的。收进 Section 时的换算：

```
relX = absX - blockMinX + 32
relY = absY - blockMinY + 56
```

## 2. 命名

格式：`NN · 区域 · 变体`（分隔符是 ` · `，U+00B7 空格中点）

| 段位 | 用途 | 实例 |
|---|---|---|
| `00` | 资源（组件母版、logo 组件） | `00 · ASSETS — Logo components` |
| `01`–`10` | 屏幕（按 版本 · 平台 · 主题 拆行） | `01 · V1 · WEB · LIGHT`、`07 · V2 · MOBILE · LIGHT` |
| `11` | 设计系统 / 组件库 | `11 · DESIGN KIT — tokens / components / states` |
| `12`–`14` | 品牌资产（logo 探索 / 生产件 / 头像） | `13 · BRAND / CODE STYLE` |
| `99` | 归档（`visible=false`，永远排最后） | `99 · ARCHIVE — 已 (hidden)` |

排序规则：取名字开头的数字，升序；`99` 自然落到最后。**不要按创建顺序排**。

## 3. 行内布局

| 场景 | 规则 |
|---|---|
| Web 屏幕行 | 4 屏 × 1440 宽，间距 80 → 行宽 6000 |
| Mobile 屏幕行 | 4 屏 × 390 宽，间距 80 → 行宽 1800 |
| 混合行（About/Lightbox/Menu） | 同一行内允许不同宽度，仍是 x 递增 + 80 间距 |
| 品牌板并排 | 大板（≥1300 高）放左列，小板叠放；列间距 48 |

行内高度不统一（Home 1329 / Post 1637），**Section 高度取该行最大高度**，不做底部对齐。

## 4. 标签处理

进 Section 前，画布上常靠浮动文字（`Label / WEB · LIGHT`）分区。

- 收进 Section 后，**浮动标签隐藏或删除**，信息由 Section 标题承担
- 若同一 Section 内还要分小行（例如「圆形裁切 160」），保留小标签，用 12–13px 的说明体
- 隐藏标签会让出它原来的 y 空间：整体上移 `标签高度 + 24`，并同步把 Section 高度减掉同样数值

## 5. 归档

- 废弃方案不删除，移入 `99 · ARCHIVE · <原因>`
- 整个 Section `visible = false`
- 归档区仍参与垂直流排（占位），避免以后恢复时和别的分区打架
- Section 名称里写明原因（`已 (hidden)`、`deprecated 2026-10`），方便日后清理

## 6. 验收三查

| 检查 | 含义 | 期望 |
|---|---|---|
| `pageOverlaps` | 顶层 Section / 画板两两相交 | `0` |
| `childOverlaps` | 同一 Section 内可见子元素相交 | `0` |
| `overflow` | 子元素越出 Section 边界 | `0` |

> 注意：检查要**排除祖先/后代关系**，否则每个容器都会被判成和自己的孩子重叠。
> `check-layout.js` 已处理。
